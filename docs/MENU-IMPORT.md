# استيراد القائمة | Menu import

لإدخال قائمة المطعم الكاملة دفعة واحدة من ملف CSV بدل إدخال كل صنف يدويًّا.

*Load the restaurant's whole menu from a CSV, instead of entering each item by
hand.*

**لماذا:** قائمة المطعم على تطبيق التوصيل نحو **١٨٤ صنفًا**
(`docs/FIELD-RESEARCH-2026-10.md`). إدخالها من لوحة الإدارة صنفًا بصنف عمل
أيّام، وفرصة كبيرة للخطأ في الأسعار.

---

## ١. الأوامر | Commands

```bash
# 1) معاينة — لا يكتب شيئًا (هذا هو الافتراضي)
npm run menu:import -- menu.csv

# 2) تنفيذ فعليّ — الأصناف الجديدة تدخل مخفيّة
npm run menu:import -- menu.csv --apply

# 3) تنفيذ مع نشر الأصناف الجديدة فورًا (بعد المراجعة)
npm run menu:import -- menu.csv --apply --publish
```

ابدأ دائمًا بالمعاينة. تعرض لك: كم صنفًا جديدًا، كم تعديلًا، **وكل تغيير في
سعر صنف موجود** — لأنه ما يُحاسَب عليه الزبون.

## ٢. الأعمدة | Columns

نموذج جاهز: [`menu-template.csv`](menu-template.csv). **احذف صفوف المثال قبل
الاستيراد.**

| العمود | مطلوب | ملاحظات |
|---|---|---|
| `category` | ✅ | اسم القسم بالعربية، أو رمزه (`pizza`). قسم غير موجود يُنشأ |
| `name_ar` | ✅ | حتى ١٢٠ حرفًا |
| `price` | ✅ | **ريال كامل**. تُقبل الأرقام العربية (`٤٥٠٠`) وفاصل الآلاف إن جمع ثلاثة أرقام (`4,500` أو `١٬٧٠٠`). **ما عدا ذلك يُرفض عمدًا**: `45,5` و`4.500` و`1.700` تُقرأ كسورًا فتُرفض، ولا تُقرأ `455` أو `4500` بالتخمين |
| `name_en` | | إن تُرك فارغًا يُعرض الاسم العربي للزائر الإنجليزي، مع تحذير |
| `description_ar`، `description_en` | | حتى ٦٠٠ حرف |
| `slug` | | حروف إنجليزية صغيرة وأرقام وشرطات. إن تُرك فارغًا يُولَّد `m-xxxxxxxx` ثابتٌ لنفس القسم والاسم |
| `status` | | `AVAILABLE` أو `SOLD_OUT` أو `HIDDEN` |
| `prep_minutes` | | من ١ إلى ١٨٠ |
| `featured` | | `true` / `false` / `نعم` / `لا` |

تُقبل أيضًا عناوين عربية: `القسم`، `الاسم`، `السعر`، `الوصف`، `الحالة`.
وإن حفظ Excel الملف بفاصلة منقوطة `;` فيُكتشف تلقائيًّا.

> ⚠️ **احفظ بصيغة «CSV UTF-8»** (من Excel: حفظ باسم ← *CSV UTF-8 (محدّد
> بفواصل)*) — **لا** «CSV» العادية. العادية في إكسل العربي تُحفظ بترميز
> Windows-1256، فيقرؤها الاستيراد حروفًا تالفة. هذا مُكتشَف ويوقف الاستيراد
> برسالة تقول ذلك، لكن الأسلم ألّا يحدث.

## ٣. القواعد | Rules

كل قاعدة هنا موجودة لسبب، وكلها مختبَرة (`tests/unit/menu-import.test.ts`):

- **أي خطأ في الملف يوقف الاستيراد كلّه.** قائمة ناقصة أسوأ من لا شيء، وكل
  الأخطاء تُعرض دفعة واحدة برقم السطر.
- **لا حذف أبدًا.** صنف غائب عن الملف لا يُمَسّ؛ «ليس في هذا الملف» لا تعني
  «يجب ألّا يوجد».
- **الخلية الفارغة تعني «لا تغيّر»، لا «امسح».** ملف فيه الأسماء والأسعار فقط
  لن يمحو الأوصاف الموجودة ولا أوقات التحضير.
- **الأصناف الجديدة تدخل مخفيّة** (`HIDDEN`) ما لم تضف `--publish` أو تضع
  `status` في الصف. لا يكون الاستيراد هو اللحظة التي تظهر فيها أسعار لم
  تُراجَع أمام الزبائن.
- **تحذير، لا خطأ، حين يتكرّر الاسم برمزين مختلفين** في القسم نفسه: غالبًا
  صنف أُدخل مرتين. قد يبيع المطعم فعلًا صنفين بالاسم نفسه، فلا يُمنع.
- **إعادة الاستيراد آمنة.** الرمز المولَّد ثابت، فالصف نفسه يحدّث الصنف نفسه
  ولا يصنع نسخة ثانية. إعادة تشغيل ملف مُنفَّذ = «لا تغيير».
- **تغيير السعر يُعرض وحده** ويُسجَّل في سجلّ التدقيق (`menu.import`) بعدد
  التغييرات.
- **الاسم الإنجليزي الحقيقي لا يُستبدل** بنسخة عربية مُملاة عند غياب `name_en`.

## ٤. ما لا يستورده | What it does not import

- **الصور.** تبقى كما هي؛ أضف صورة الطبق من لوحة الإدارة.
- **مجموعات الخيارات** (الأحجام، الإضافات). هذه تُضاف من لوحة الإدارة.
- **الأحجام «العادي / هاوس».** على تطبيق التوصيل تظهر كصنفين منفصلين بفرق
  ثابت تقريبًا (+٥٠٠ إلى +١٬٠٠٠). لو استوردتهما كما هما صار عندك صنفان؛
  الأنسب غالبًا صنف واحد بمجموعة خيار «الحجم». قرّر ذلك مع المالك **قبل**
  الاستيراد، لأن تحويل صنفين إلى صنف بخيار بعده عمل يدويّ.

## ٥. بعد الاستيراد

1. افتح **الإدارة ← المنتجات** وراجع الأصناف المخفيّة وأسعارها.
2. اجعل ما راجعته «متاحًا».
3. أضف الصور.

## ٦. مصدر الملف

مصدر الأسعار هو **المالك**. قائمة تطبيق التوصيل قد تحمل هامش توصيل، وأسعارها
تختلف عن أسعارنا في الاتجاهين، فلا تُستورَد دون أن يؤكّدها. إن كانت لوحة
التطبيق تتيح تصدير القائمة فاطلبه منه؛ وإلا فانسخ القائمة إلى النموذج.
